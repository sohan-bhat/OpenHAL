# OpenHAL 0.1.0

OpenHAL is an open-source protocol for AI agents to control hardware. An agent sends a command to the OpenHAL hub, and the hub's safety kernel checks the command against limits a person confirmed before any driver acts. This is the first release.

## Try the demo

The demo needs no hardware and no API key. An agent babysits a 3D print on a simulated Klipper printer and camera, has a nozzle temperature over the limit blocked and holds a cancel for a person to approve.

```text
uvx halkit demo
```

With pipx instead of uv, run `pipx run halkit demo`.

## Install

On macOS and Linux, run this command in a terminal.

```text
curl -LsSf https://sohan-bhat.github.io/OpenHAL/install.sh | sh
```

On Windows, run this command in PowerShell.

```text
irm https://sohan-bhat.github.io/OpenHAL/install.ps1 | iex
```

With uv or pipx, run `uv tool install halkit` or `pipx install halkit`. OpenHAL runs on Python 3.12, 3.13, 3.14 and 3.15. Then run `openhal init` to set up the hub, your devices and your AI clients. [The install guide](https://github.com/sohan-bhat/OpenHAL/blob/v0.1.0/docs/guide/install.md) has every step.

The package on PyPI is `halkit`, and the command is `openhal`. The `openhal` package on PyPI is a different project.

## What's in 0.1.0

- Specification v0.1, with the device file format, the hub protocol and a conformance suite for drivers.
- The safety kernel, with units, limits, rate of change, interlocks, watchdogs, risk levels, one stop for every device and a hash-chained audit log.
- The hub, with a REST API, the hub protocol over WebSocket and stdio, and an MCP server with 36 tools for Claude Desktop, Claude Code, Cursor and other MCP clients.
- 35 drivers, each tested against a simulator, from serial and Firmata to Klipper, SCPI instruments, Home Assistant, ESPHome, MQTT, Modbus, ROS 2 and OPC UA.
- The OpenHAL Arduino library, the Inspector dashboard, the driver writer, routines and the Python client.

[CHANGELOG.md](https://github.com/sohan-bhat/OpenHAL/blob/v0.1.0/CHANGELOG.md) lists everything.

## Before you connect real hardware

- No driver has been tested on real hardware yet. Every driver passes the conformance suite against a simulator, and every driver has a step-by-step hardware test plan in [docs/hardware-tests](https://github.com/sohan-bhat/OpenHAL/tree/v0.1.0/docs/hardware-tests), lowest risk first.
- Every file in the device library is unverified until a person checks the file's limits.
- Windows has no background service yet, so run `openhal start` in a terminal there.
- Report a safety problem privately, as [SECURITY.md](https://github.com/sohan-bhat/OpenHAL/blob/v0.1.0/SECURITY.md) describes.
