# Brief: the starter library (M12)

Read docs/agents/COMMON.md first. Then read spec/2026-10-24/device-files.md, openhal/spec/models.py, openhal/hub/discovery.py (library paths and matching), openhal/drivers/registry.py, and the example files and tests of a few drivers, such as openhal/drivers/scpi/, openhal/drivers/modbus/ and tests/drivers/modbus/test_modbus.py.

## Goal

A device library the hub matches discovered devices against, with at least 30 device files for real products, all unverified and loading read-only until a person confirms them.

1. Files live in `library/<driver package>/<maker>-<model>.hal.yaml` at the repo root. The hub already looks there (`REPO_LIBRARY`) and in `openhal/library_data` (`BUNDLED_LIBRARY`). Add a force-include in pyproject.toml so the wheel ships `library/` as `openhal/library_data`.
2. Cover at least these families, with real products and real identifiers.
   - Arduino and ESP32 boards running the OpenHAL firmware, including the plant waterer from examples/plant-waterer/
   - SCPI multimeters, power supplies and oscilloscopes (for example Rigol DP832, Siglent SPD3303X, Keysight 34461A, Siglent SDM3045X, Rigol DS1054Z)
   - Klipper printers through Moonraker and Marlin printers over serial
   - Raspberry Pi GPIO and the Pi camera
   - MQTT and ESPHome sensors
   - Modbus energy meters (for example Eastron SDM120 and SDM630)
   - MIDI controllers (for example Akai LPD8 and Korg nanoKONTROL2)
   - BLE sensors (for example Xiaomi LYWSD03MMC)
   - Home Assistant plugs and lights
   - A telescope mount through ASCOM Alpaca
3. Every file
   - validates with `openhal file validate` and constructs its driver, the way tests/drivers/modbus/test_modbus.py does with its examples
   - has `match` identifiers the driver's discover() really reports, so discovery can find it. Research USB ids, SCPI `*IDN?` strings, BLE names and mDNS types and cite sources in docs/research/SOURCES.md
   - marks every write channel and every action `suggested: true` and has no `confirmed` anywhere
   - has `provenance: { source: library, by: OpenHAL starter library, at: 2026-10-25, verification: { status: unverified } }`
   - has conservative limits (the lowest sensible maximums, confirmation tiers on anything with heat, motion or mains power) and `notes` that start with "Suggested limits. A person must confirm every limit before this device can be written."
   - uses the one value format (ADR 0016) anywhere a value appears
4. A small CLI so people can use the library.
   - `openhal library list [--driver NAME] [--json]`
   - `openhal library show NAME`
   - `openhal library add NAME` copies the file into the hub's devices folder, never adds `confirmed`, and refuses to overwrite an existing file
   - `openhal discover` tells the person to run `openhal library add` for a match that has no device file yet
5. `library/README.md` lists every file by family, generated by a script, with a test that it is current. docs/guide/library.md explains how matching, suggested limits and confirmation work, in short plain sentences.

## Tests (tests/library/)

Every file loads read-only, constructs its driver, has suggested limits everywhere and no confirmation, has library provenance and at least one match identifier, ids are unique, and discovery with a synthetic `Discovered` built from each file's identifiers picks that file over every other library file. The library README is current. The CLI commands work against a temp home, including the refusal to overwrite.

## Files you own

library/, tests/library/, openhal/cli/library_cmd.py, the one registration line in openhal/cli/main.py, the discover output in openhal/cli/hub_cmd.py, openhal/hub/discovery.py only if matching needs a fix, docs/guide/library.md, docs/research/SOURCES.md (append only), the force-include line in pyproject.toml, and a new section at the end of docs/interfaces/CLI.md.

## Not yours

Driver packages and their examples, the spec, the kernel, the README and everything else. If a driver can't express a product's channels, list it in your report as a proposal instead of changing the driver.
